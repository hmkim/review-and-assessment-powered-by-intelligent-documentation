# 한국어 예제 유스케이스

RAPID(Review and Assessment Powered by Intelligent Documentation)를 한국어 환경에서 바로 시험해 볼 수 있도록 준비한 예제 모음입니다. 각 유스케이스는 **체크리스트 문서**(심사 기준이 되는 PDF)와 **심사 대상 문서**(점검받을 PDF)로 이루어져 있고, 일부는 **Knowledge Base**(심사 근거로 참조할 텍스트 파일)를 함께 제공합니다.

| 유스케이스 | 분야 | 사용하는 RAPID 기능 | 심사 대상 문서에 숨긴 결함 |
| --- | --- | --- | --- |
| [001 개인정보 처리방침 점검](#유스케이스-001-개인정보-처리방침-점검) | 전 산업 (기업 거버넌스) | Knowledge Base | 6개 |
| [002 건축허가 설계개요 검산](#유스케이스-002-건축허가-설계개요-검산) | 건설·부동산 | Code Interpreter (수치 재계산) | 3개 |
| [003 위험성평가 결과서 점검](#유스케이스-003-위험성평가-결과서-점검) | 제조 (산업안전) | 기본 | 5개 |

## 이 예제의 특징

- **체크리스트 문서는 실제 공개 문서를 바탕으로 만들었습니다.** 법령(「개인정보 보호법」, 「건축법」 등)·시행령·고용노동부 고시의 조문 원문을 국가법령정보센터에서 그대로 가져와 수록했습니다. "회사가 이미 가지고 있는 규정 PDF를 올리면 체크리스트가 된다"는 RAPID의 사용 방식을 실제 문서로 체험할 수 있습니다.
- **심사 대상 문서는 모두 가상입니다.** 회사명·인명·주소·수치는 전부 만들어 낸 것이며, AI 심사가 찾아내야 할 결함을 의도적으로 넣었습니다. 정답은 아래 각 유스케이스의 "숨긴 결함" 표에 있습니다.
- **한국어 PDF 폰트**: 문서는 Noto Sans KR(SIL Open Font License)을 임베딩해 생성했으므로 어느 환경에서 열어도 한글이 깨지지 않습니다.

## 사전 준비

1. RAPID 배포 후 로그인하고, 화면 오른쪽 위 언어를 **한국어**로 바꿉니다. (AI 심사 결과도 한국어로 출력됩니다.)
2. 아래 유스케이스에서 체크리스트 PDF를 내려받아 **체크리스트 > 새 체크리스트**로 업로드합니다. 추출된 항목을 확인·수정합니다.
3. 심사 대상 PDF를 **심사 > 새 심사**로 업로드하고 체크리스트를 선택해 심사를 실행합니다.
4. Knowledge Base가 필요한 유스케이스(001)는 아래 절차로 먼저 데이터 소스를 등록합니다.

> **HWP/HWPX 문서는 PDF로 변환해 업로드하세요.** 한국 공공기관·기업 문서는 한글(HWP) 형식이 많지만 RAPID는 PDF·이미지·텍스트 파일만 처리합니다. 한컴오피스의 "PDF로 저장" 또는 한컴 PDF 변환 기능을 사용해 PDF로 바꾼 뒤 업로드하면 됩니다. 이 예제의 법령 문서도 국가법령정보센터가 제공하는 PDF 서식을 사용했습니다.

## 유스케이스 001: 개인정보 처리방침 점검

**상황**: 회사가 홈페이지에 게재한 개인정보 처리방침이 「개인정보 보호법」 제30조와 개인정보보호위원회 「개인정보 처리방침 작성지침」(2026.4.)이 요구하는 기재 사항을 모두 갖추고 있는지 점검합니다. 개인정보 보호 담당 부서, 법무·컴플라이언스 부서, 또는 처리방침 작성을 대행하는 컨설팅 회사의 업무에 해당합니다.

**폴더**: `use_case_001_privacy_policy_review/`

### Knowledge Base 설정

1. AWS 콘솔에서 Amazon Bedrock Knowledge Base를 만들고, `knowledge_base_sources/` 의 txt 파일 5개를 S3 데이터 소스로 등록한 뒤 동기화합니다. (설정 방법은 [영어 README 유스케이스 005의 Knowledge Base 안내](../en/README.md#use-case-005-sustainability-assessment-energy-efficiency-compliance)와 같습니다.)
2. RAPID에서 체크리스트를 만들 때 **Knowledge Base ID**를 입력합니다. 심사 결과에 "작성지침 Ⅲ-5에 따르면 보유기간은 구체적인 기간으로 기재해야 하나…"처럼 근거를 인용하는 설명이 붙습니다.
3. Knowledge Base 없이도 심사는 동작합니다. 다만 결함의 근거가 체크리스트 본문(법령 원문·점검 기준) 범위로 한정됩니다.

## 유스케이스 002: 건축허가 설계개요 검산

**상황**: 건축허가를 신청하기 전에 설계사무소가 작성한 **설계개요서**(대지면적·건축면적·연면적·건폐율·용적률 등을 한 장에 요약한 표)의 수치가 서로 맞는지, 법정 상한 이내인지 사전 검토합니다. 건축주(발주처)의 사업 담당자, 감리, 허가 대행 담당자의 업무에 해당합니다. 비율 항목을 기재값 그대로 믿지 않고 **원자료로부터 다시 계산**해 비교하는 것이 핵심이며, RAPID의 Code Interpreter가 이 계산을 수행합니다.

**폴더**: `use_case_002_building_design_summary_check/`

| 파일 | 역할 | 내용 |
| --- | --- | --- |
| `건축허가_설계개요_검산_체크리스트.pdf` | 체크리스트 | 「건축법」 제42·55·56조, 「건축법 시행령」 제119조(발췌), 「국토의 계획 및 이용에 관한 법률 시행령」 제84·85조 원문 + 검산 항목 9개와 검산 공식 (4쪽) |
| `심사대상_근린생활시설_신축_설계개요서.pdf` | 심사 대상 | 가상의 「가온누리빌딩 근린생활시설 신축공사」 설계개요서 (2쪽). 항목 구성은 「건축법 시행규칙」 [별지 제1호의4서식] 건축허가신청서의 설계개요 항목을 따름 |

### 숨긴 결함 (정답)

설계개요서의 원자료: 대지면적 660.00㎡, 건축면적 389.40㎡, 층별 바닥면적 지하1층 350.00 / 1층 389.40 / 2층 389.40 / 3층 352.60 / 4층 320.00㎡, 용도지역 제2종일반주거지역.

| # | 결함 | 재계산 결과 |
| --- | --- | --- |
| 1 | **용적률 272.94%** 로 기재. 용적률 산정용 연면적을 지하층(350.00㎡)까지 포함한 1,801.40㎡로 잡음 | 시행령 제119조①4호가목에 따라 지하층 면적을 빼면 1,451.40㎡ → 용적률 **219.91%** (상한 250% 이내). 기재값 기준으로는 상한 초과로 보이지만 실제로는 기재 오류 |
| 2 | 층별 면적표 **합계란 1,811.40㎡** | 각 층의 합은 **1,801.40㎡**. 면적 개요의 연면적(1,801.40㎡)과도 불일치 |
| 3 | **조경면적 란이 공란** | 대지면적 200㎡ 이상이므로 건축법 제42조에 따라 조경 계획 기재 필요 (기준 수치는 지자체 조례 사항이므로 기재 여부만 점검) |

건폐율 59.00%(= 389.40 ÷ 660.00 × 100, 상한 60%), 층수·높이, 주차 계획(법정 8대 ≤ 계획 9대)은 정상입니다.

> 체크리스트는 지자체 **조례**가 아니라 시행령의 용도지역별 **상한**만 기준으로 삼습니다. 실제 허가 검토에서는 해당 지자체 조례(더 강화된 건폐율·용적률, 조경·주차 기준)를 별도로 확인해야 합니다.

## 유스케이스 003: 위험성평가 결과서 점검

**상황**: 제조 사업장이 작성한 **위험성평가 결과서**(공정의 위험 요인을 찾아 위험 정도를 평가하고 개선 대책을 세운 보고서)가 「사업장 위험성평가에 관한 지침」(고용노동부고시 제2024-76호)이 정한 절차를 빠짐없이 거쳤는지 점검합니다. 본사 안전보건 조직이 사업장 보고서를 검토하거나, 안전 컨설팅 회사가 고객 사업장을 점검하는 업무에 해당합니다.

**폴더**: `use_case_003_risk_assessment_report/`

| 파일 | 역할 | 내용 |
| --- | --- | --- |
| `위험성평가_실시_점검_체크리스트.pdf` | 체크리스트 | 「산업안전보건법 시행규칙」 제37조, 고시 제5조의2·제6~15조 원문 + 점검 항목 14개 (5쪽) |
| `심사대상_프레스공정_위험성평가_결과서.pdf` | 심사 대상 | 가상의 「(주)한빛정밀」 프레스 공정 2026년 정기 위험성평가 결과서 (2쪽) |

### 숨긴 결함 (정답)

| # | 결함 | 근거 |
| --- | --- | --- |
| 1 | 평가팀이 공장장·안전관리자·생산팀장·설비팀장으로만 구성되어 **해당 작업 근로자(또는 근로자대표)의 참여 기록이 없음** | 고시 제6조 |
| 2 | 위험성 판단 기준(빈도×강도) 표는 있지만 **허용 가능한 위험성 수준이 공란** ("평가팀 협의 후 기재") | 고시 제9조②2 |
| 3 | 감소대책 표에서 소음(No.4)·유류 누출(No.6)의 **담당자와 완료 기한이 비어 있음** | 고시 제12조① |
| 4 | **'이행 후 위험성' 열이 전부 "-"** — 감소대책 실행 후 위험성을 다시 확인한 기록이 없음 | 고시 제12조②③ |
| 5 | 위험성 9(최고)인 금형 교체 중 끼임(No.1)에 **보호구 착용·주의 교육만** 대책으로 수립. 공학적 대책(양수조작식·광전자식 방호장치, 안전블록 등)의 검토가 없어 감소대책 우선순위를 따르지 않음 | 고시 제12조① 각 호의 순서 |

실시규정 요약, 사전 안전보건정보 조사, 유해·위험요인 파악 방법(순회점검 + 근로자 제안), 결과 게시·TBM 공유, 기록 보존(3년)은 정상입니다.

## 용어 풀이

| 용어 | 쉬운 설명 |
| --- | --- |
| 개인정보 처리방침 | 회사가 고객의 개인정보를 어떤 목적으로 모아서 얼마나 보관하고 누구에게 넘기는지 등을 적어 홈페이지에 공개하는 문서. 법으로 기재 항목이 정해져 있다. |
| 정보주체 | 개인정보의 주인, 즉 그 정보가 가리키는 사람 (고객·회원 본인). |
| 보유·이용기간 | 회사가 개인정보를 가지고 있을 수 있는 기간. "목적 달성 시까지"처럼 막연하게 쓰면 안 되고 구체적 기간이나 기준을 써야 한다. |
| 파기 | 더 필요 없게 된 개인정보를 복구할 수 없게 지우는 것. 절차와 방법을 처리방침에 적어야 한다. |
| 국외 이전 | 개인정보를 외국에 있는 회사(예: 해외 호텔)에 보내는 것. 어디로·왜·얼마나 보내는지, 거부할 방법이 있는지 알려야 한다. |
| Knowledge Base | AI가 심사할 때 참고하도록 미리 올려 둔 자료 모음(여기서는 법령 원문과 작성지침 발췌). 심사 결과에 "지침 ○○에 따르면…"과 같은 근거 인용이 붙게 한다. |
| 건폐율 | 대지(땅) 면적 중 건물이 덮고 있는 바닥(건축면적)의 비율. 60%면 땅의 60%에만 건물을 올릴 수 있다. |
| 용적률 | 대지 면적에 대한 건물 전체 층 면적 합(연면적)의 비율. 지하층과 부속 주차장 면적은 빼고 계산한다. 높은 건물을 얼마나 지을 수 있는지를 정한다. |
| 연면적 | 건물의 각 층 바닥 면적을 모두 더한 값. |
| 용도지역 | 국가가 땅마다 정해 둔 쓰임새 구분(주거지역·상업지역 등). 지역마다 건폐율·용적률 상한이 다르다. |
| 설계개요서 | 건물의 면적·높이·층수·주차 등 핵심 수치를 한 장에 요약한 표. 건축허가 신청서의 첨부 항목이다. |
| Code Interpreter | AI가 문서의 숫자를 꺼내 실제로 계산(나누기·합계 등)을 실행해 검산하는 RAPID 기능. |
| 위험성평가 | 사업장에서 다칠 수 있는 요인(끼임·소음 등)을 찾아, 얼마나 위험한지 점수를 매기고, 줄이는 대책을 세우는 법정 절차. 매년 1회 이상 해야 한다. |
| 빈도·강도법 | 위험성을 "얼마나 자주 일어날 수 있는가(빈도) × 일어나면 얼마나 심한가(강도)"로 점수 매기는 방법. |
| 허용 가능한 위험성 수준 | 이 점수 이하면 그대로 두어도 된다고 사업장이 미리 정한 기준선. 평가 전에 정해 두어야 한다. |
| 감소대책 우선순위 | 위험을 줄일 때 "위험한 작업 자체를 없애기 → 기계적 안전장치(공학적) → 작업 절차·교육(관리적) → 보호구" 순으로 먼저 검토해야 한다는 원칙. |
| TBM (Tool Box Meeting) | 작업 시작 전 현장에서 짧게 모여 그날의 위험과 주의사항을 공유하는 회의. |

## 문서 다시 생성하기

PDF 6개와 `KB_01` 텍스트는 `.claude/skills/add-example/scripts/create_korean_example_pdfs.py` 가 생성합니다. 내용은 `scripts/korean_examples/` 의 모듈에, 법령 원문은 `law_texts.py` 에 있습니다 (원문은 손으로 수정하지 않습니다).

```bash
cd .claude/skills/add-example
uv run --no-project --with "reportlab>=4" --with "fonttools>=4.40" python scripts/create_korean_example_pdfs.py
# 폰트는 google/fonts 고정 커밋에서 ~/.cache/rapid-ko-fonts/ 로 내려받아 sha256 을 검증합니다. 오프라인이면 --font 로 로컬 파일 지정.

# KB_02~05 (작성지침 발췌) 는 원문 PDF 가 필요합니다 (레포에 포함하지 않음):
uv run --no-project --with pypdf python scripts/extract_pipc_guideline_kb.py <작성지침.pdf>

# 썸네일
uv run --no-project --with pypdfium2 --with Pillow python scripts/generate_thumbnails.py --lang ko
```
