결론: **한국어 PDF에 대한 심사 품질은 일본어·영어와 같은 기준선에서 사용 가능한 수준**입니다. 결함(fail) 케이스는 285건 모두 놓치지 않았고, 출력은 전부 한국어였습니다. 개선이 필요한 것은 모델의 한국어 능력이 아니라 **(a) 근거 부족 때 extractedText를 비우라는 프롬프트 규약이 한국어에서도 거의 지켜지지 않는 점**과 **(b) 평가 세트의 '정상' 라벨 3개가 사실상 모호했던 점**입니다.

- **"다른 쪽 일치"는 오류가 아닙니다.** 결과 JSON의 `pageNumber`는 한 개인데 인용은 여러 쪽에 걸치므로(예: 1쪽 표 + 2쪽 조항), 첫 인용 외의 구절은 다른 쪽에서 일치합니다.
- **텍스트 PDF 불일치 10건**은 모두 모델이 표의 여러 셀을 `/`로 이어 붙여 한 문장으로 재조합한 경우입니다(예: `용적률 산정용 연면적 1,801.40 ㎡ / 용적률 272.94 % / 법정 상한 250 %`). 포함율 0.84~1.00이므로 문서에 없는 내용을 만든 것은 없습니다. 이 10건은 Bedrock Citations 블록이 아니라 모델이 JSON `extractedText`에 직접 쓴 값으로, 코드의 폴백 경로를 탄 것입니다.
- **D2(띄어쓰기 소실 텍스트)에서도 인용 정합이 유지**됐습니다(6케이스 × 3회, 불일치 1건·포함율 1.00). 띄어쓰기 없는 원문이 Citations에 문제를 일으킬 것이라는 사전 우려는 해소됐습니다.
- **스캔 PDF**에서는 Bedrock이 텍스트 레이어가 없어 인용을 **이미지에서 읽어 재구성**합니다. 37건의 "불일치"는 원본 PDF 대비 토큰 포함율 0.87~1.00으로, 표 셀 순서 재배치·`／` 구분자 삽입이 원인이고 수치는 모두 원본과 같았습니다. 다만 UI에서 "원문 그대로"가 아니라는 점은 사용자에게 안내할 가치가 있습니다.

**제안 (Q8).** 프롬프트에 "법령·규정 원문, 참고 자료, 머리말·판정 방법 설명은 점검 항목으로 만들지 말고, 점검 항목 표(또는 번호가 매겨진 점검 문항)만 추출"하는 지시를 추가하고, 설계 체크리스트 3건으로 재측정합니다(기대: 추출 항목 ≈ designed + 소수 meta, 조문 오추출 ≤ 20%). 한국어 예제의 체크리스트 PDF에는 "제2장은 참고용 원문입니다"를 머리말에 명시하는 것도 병행할 수 있지만, 프롬프트 수정 없이는 효과가 불확실합니다.

제안 1,254건(중앙 115자)은 전부 한국어였고, 백엔드가 "모호하지 않음"을 판별하는 영문 기호 `NO_AMBIGUOUS`가 제안문에 섞여 나온 경우는 없었습니다(백엔드는 응답이 정확히 `NO_AMBIGUOUS`일 때만 비모호로 처리하므로, 기호에 설명이 붙으면 모호로 오판됩니다 — 이번 측정에서는 0건). 제안 내용은 실무적으로 타당합니다. 예: UC002 "주차장 배치 일치 확인"에 대해 "'계획 대수'가 총 대수인지 지하·지상 구분별인지, 장애인·전기차 주차를 포함하는지 명시", "허용 오차(예: 0대)를 제시" 등.

플래그 비율은 문서 성격을 반영합니다. 설계 항목 중 플래그된 것은 UC001 25/40(점검 기준이 "구체적으로", "불명확한 표현" 같은 판단어를 포함한 항목), UC002 3/16, UC003 5/14였고, 조문을 옮긴 항목(`law_verbatim`)은 UC003 37/91이 플래그됐습니다 — 조문은 원래 점검 기준으로 쓰기엔 모호하므로 당연한 결과이고, 조문 오추출(Q8)이 모호성 검출 부하까지 키우는 연쇄 효과입니다.

**D2 실패 원인(확인).** 모호성 검출 워커 Lambda는 제한 시간 15분(`cdk/lib/constructs/ambiguity-detection-processor.ts`, `timeout: Duration.minutes(15)`)에 항목을 **직렬**(기본 동시성 1)로 처리합니다. D2는 leaf 항목 365개 × 5.2 s ≈ 32분이 필요해 170개를 처리한 01:45:00Z에 `Task timed out`(CloudWatch REPORT `Duration: 900000.00 ms ... Status: timeout`)으로 끊겼고, SQS가 2분 뒤 같은 메시지를 재전달해(`maxReceiveCount: 2`) 두 번째 시도도 같은 조건으로 시작했습니다. 처리된 170개 중 100개가 플래그된 것은 우연한 숫자입니다. 항목 170개 이상인 체크리스트(일본어·영어 포함)는 모두 같은 방식으로 실패하며, 처리 도중의 플래그는 저장되지만 세트 상태는 `failed`로 남습니다.

**제안 (Q9).** (1) 모호성 검출을 항목 배치로 나누어 SQS 메시지 여러 개로 보내거나 Step Functions Map으로 바꿔 15분 제한에서 분리, 또는 최소한 동시성(`CHECKLIST_INLINE_MAP_CONCURRENCY`)을 4~8로 올림. (2) 부분 완료 상태를 UI에 표시. (3) Q8의 조문 오추출을 줄이면 대상 항목 수 자체가 1/4~1/10로 줄어 이 문제가 거의 사라집니다. (4) 실패 시 UI의 `errorSummary`가 일본어 하드코딩(「...」の処理中にエラーが発生しました)인 점은 M1 후속 수정 대상.

## 5. 제안 (프롬프트·세트·코드)

수용 기준 미달 항목과 측정 중 발견한 사항에 한정합니다. 모두 upstream에도 해당하므로 한국어 PR과 분리해 제안합니다.

1. **근거 부족 규약 재정의 (Q7)** — **구현·검증함** (`008c979`): 문서 프롬프트의 "extractedText는 공백" 규칙을 "정보 부재를 보여주는 구절만 인용"으로 바꾸고, 프롬프트 3종에 언어별 표준 접두어(`근거 불충분:` / `証拠不十分:` / `Insufficient evidence:`)를 지시. 변경 전 5/18(ko)·2/18(ja)·0/9(en 문서) → 변경 후 표준 문구 51/51, confidence 규칙 51/51(§4.6). upstream 제안서에 전/후 수치 반영.
2. **JSON 안정성 (Q2)** — **구현함**: `_extract_json_from_message`에 문자열 값 안의 미이스케이프 큰따옴표를 복구하는 2차 파싱(`_repair_unescaped_quotes`)을 추가했고, 실제 실패 payload로 단위 테스트를 작성했습니다. 프롬프트에 "직접 인용은 「」 사용" 지시를 더하는 것은 선택 사항으로 남깁니다.
3. **평가 세트 수정 (Q5)** — **구현·확인함**: §4.5 "수정 후 재실행" 참조(3항목 × 3회 9/9, 전체 40/40).
4. **토큰 집계 보완 (Q11)** — **구현함**: `ReviewMetaTracker.get_review_meta`가 `cacheReadInputTokens`·`cacheWriteInputTokens`를 `input_tokens`에 합산하고(내역은 `uncached_input_tokens`·`cache_read_input_tokens`·`cache_write_input_tokens`로 별도 기록) 비용을 캐시 단가(읽기 10%, 쓰기 125%)로 계산합니다. 수정 전에는 UI의 비용 표시가 입력 비용을 거의 0으로 보여 주었습니다. 다음 평가 실행부터 Q11 입력 토큰이 결과 JSON에 직접 기록됩니다.
5. **스캔 PDF 안내** — 텍스트 레이어가 없는 PDF에서는 추출 텍스트가 OCR 재구성이라는 점을 `examples/ko/README.md`와 UI 도움말에 한 줄 추가.
6. **체크리스트 추출 백엔드 수정 (Q8)** — **구현함** (`61034c7`, `097a85f`, 이번 커밋): 인용 블록 결합, 출력 토큰 한도 16k, `<cite>` 태그 제거. 셋 다 upstream 공통 결함(§4.8 표). `<cite>` 제거는 재배포 후 UC003 재실행으로 확인 필요.
7. **추출 프롬프트에 참고 자료 제외 지시 (Q8)** — 미구현. "법령·규정 원문과 설명 문단은 항목이 아니며 점검 항목 표만 추출"을 지시하고 설계 체크리스트 3건으로 재측정. 조문 오추출이 줄면 모호성 검출 시간·실패(Q9)도 함께 해소됩니다.
8. **모호성 검출 15분 제한 (Q9)** — 미구현. 배치 분할 또는 동시성 상향(§4.9 제안). 170개 이상 항목 세트는 언어와 무관하게 실패합니다.
9. **체크리스트가 아닌 문서 감지 (Q8)** — 검토 제안. 신청서 양식에서 67개 항목이 나왔으므로, 추출 결과에 "점검 항목으로 보이는 비율"을 함께 반환해 UI가 경고하는 방식을 검토.
