- **"다른 쪽 일치"는 오류가 아닙니다.** 결과 JSON의 `pageNumber`는 한 개인데 인용은 여러 쪽에 걸치므로(예: 1쪽 표 + 2쪽 조항), 첫 인용 외의 구절은 다른 쪽에서 일치합니다.
- **텍스트 PDF 불일치 10건**은 모두 모델이 표의 여러 셀을 `/`로 이어 붙여 한 문장으로 재조합한 경우입니다(예: `용적률 산정용 연면적 1,801.40 ㎡ / 용적률 272.94 % / 법정 상한 250 %`). 포함율 0.84~1.00이므로 문서에 없는 내용을 만든 것은 없습니다. 이 10건은 Bedrock Citations 블록이 아니라 모델이 JSON `extractedText`에 직접 쓴 값으로, 코드의 폴백 경로를 탄 것입니다.
- **D2(띄어쓰기 소실 텍스트)에서도 인용 정합이 유지**됐습니다(6케이스 × 3회, 불일치 1건·포함율 1.00). 띄어쓰기 없는 원문이 Citations에 문제를 일으킬 것이라는 사전 우려는 해소됐습니다.
- **스캔 PDF**에서는 Bedrock이 텍스트 레이어가 없어 인용을 **이미지에서 읽어 재구성**합니다. 37건의 "불일치"는 원본 PDF 대비 토큰 포함율 0.87~1.00으로, 표 셀 순서 재배치·`／` 구분자 삽입이 원인이고 수치는 모두 원본과 같았습니다. 다만 UI에서 "원문 그대로"가 아니라는 점은 사용자에게 안내할 가치가 있습니다.

## 5. 제안 (프롬프트·세트·코드)

4. **토큰 집계 보완 (Q11)** — **구현함**: `ReviewMetaTracker.get_review_meta`가 `cacheReadInputTokens`·`cacheWriteInputTokens`를 `input_tokens`에 합산하고(내역은 `uncached_input_tokens`·`cache_read_input_tokens`·`cache_write_input_tokens`로 별도 기록) 비용을 캐시 단가(읽기 10%, 쓰기 125%)로 계산합니다. 수정 전에는 UI의 비용 표시가 입력 비용을 거의 0으로 보여 주었습니다. 다음 평가 실행부터 Q11 입력 토큰이 결과 JSON에 직접 기록됩니다.

```bash
cd review-item-processor
```
